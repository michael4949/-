# AlphaGym 技术方案

> 面向决策的完整方案：数据源选型与授权路径、系统架构、AI 能力技术栈、
> 合规边界、里程碑排期、风险登记。
>
> 本文所有「已实现」的部分都能在本仓库跑起来（`npm test` 49 项 + 管道自检 9 项）；
> 「待建」的部分明确标注，不与已实现内容混写。

---

## 0. 一页纸摘要

**产品命题**：不是「带 AI 的复盘软件」，而是**能证明交易能力的评估系统**。

传统复盘软件（交易练习者 / 心忆复盘 / 盘立方）卖的是「回放 + 图表」。
它们给出胜率 54%、收益 +27% 这类数字，但**无法区分「你有优势」和「这段行情好」**。
这个区分恰恰是所有交易者最想知道、也最没人回答的问题。

**技术护城河不在 AI，在两件更硬的事**：
1. 一套**校准过的**统计评估引擎（p 值是真的 p 值，有实测数据支撑）；
2. 一套**未来数据在架构上不可达**的回放内核（这决定了成绩能否用于选拔与排行）。

大模型只做最后一公里的翻译层，不参与判断 —— 这既杜绝幻觉，也划清了合规边界。

**为什么这条路 TEx 追不上**：不是功能多寡问题。他们的产品结构是「工具」，
评估系统需要的服务端权威撮合、可审计操作日志、统计校准体系，
是要从架构层重做的，而不是加几个功能页。

## 1. 竞争定位

### 1.1 TEx（交易练习者）的实际形态

| 维度 | 现状 |
|---|---|
| 产品 | PC 版《交易练习者》+ 手机版《TEx 交易练习课堂》+《财报掘金者》 |
| 商业模式 | 一次买断 + 数据年费；正式版赠 1 年手机版高级会员（标价 198 元/年） |
| 数据 | 内盘股票/可转债/期货，免费版限最近 3 个月回放、300 条交易记录、无云同步 |
| 存续 | 2013 年至今十年以上迭代，多下载站收录，帮助文档与升级日志完整 |
| 公开短板 | **无逐笔复盘**（仅逐 K 回放），功能性弱于心忆复盘/盘立方 |
| 变现延伸 | 导流至「增上选拔」实盘选拔赛（三阶段，实盘赛 50% 盈利分成） |

**结论**：TEx 是一个运营了十年的、结构健康的工具软件生意。
它的护城河是**数据积累与用户习惯**，不是技术。它的天花板是「工具」这个品类本身 ——
工具卖一次性授权，无法从用户的持续成长中获得收入。

### 1.2 我们的切入点

不去正面比拼「回放功能谁更全」（那是十年积累，短期追不上），
而是**换赛道**：从「提供工具」变成「提供评估与训练」。

| | 工具（TEx） | 评估系统（AlphaGym） |
|---|---|---|
| 卖什么 | 软件授权 + 数据 | 持续的能力评估与训练路径 |
| 计价 | 买断 + 年费 | 订阅 / 训练营 / B 端 SaaS |
| 用户离开的成本 | 换个软件 | 丢掉自己的能力成长档案 |
| 天花板 | 散户工具市场 | + 期货公司/私募的交易员培训与选拔 |

## 2. 数据层

### 2.1 一个决定可行性的判断

**回放训练不需要实时行情，只需要历史数据。**

这句话的分量：历史数据授权成本比实时行情低一到两个数量级，
且不涉及交易所实时行情的转发资质。这是这个品类相对于任何「行情类」产品的
结构性成本优势，应当写进商业计划的第一页。

### 2.2 数据源分层

| 层级 | 来源 | 用途 | 授权风险 |
|---|---|---|---|
| 起步/MVP | AkShare、Baostock、Tushare | A股日线分钟、期货日线、财报 | 🔴 仅限个人研究自用，**再分发违规** |
| 必备 | 中金所/上期所/大商所/郑商所官网 | 合约规格、保证金率、手续费率表、交易日历（含夜盘） | 🟢 公开数据 |
| 商用 | 通联数据、聚宽、东方财富 Choice、同花顺 iFinD、Wind | 分钟/tick、财务数据 | 🟡 需明确谈「终端展示」授权 |
| 兜底 | BYOD 用户自带数据导入 | 全部 | 🟢 风险转移给用户，同时是差异化功能 |

### 2.3 ⚠️ 授权是第一优先级，不是技术问题

**产品把数据下发到客户端 = 再分发。** 绝大多数数据商合同明文禁止。

这一条决定产品形态，必须在写第一行业务代码之前谈清楚：

- 谈得下来 → 客户端本地缓存 + 分片下发（性能最优，体验最好）
- 谈不下来 → 数据必须留在服务端，客户端只拿渲染结果或极短窗口切片
  （对回放这种高频拉取场景，网络往返会成为体验瓶颈，需要专门设计）
- 都不行 → 走 BYOD，把产品定位为「你的数据 + 我们的评估引擎」

**建议动作**：立项第一周就向 2–3 家数据商发询价，明确提出
「终端展示 + 客户端缓存」的授权诉求，拿到书面条款再定架构。
具体报价随品种范围、历史深度、并发量差异很大，此处不做臆测。

### 2.4 数据工程要点（已实现，`tools/akshare_pipeline.py`）

已实现并通过离线自检（9 项）：

**① 复权处理 —— 最容易犯的隐蔽错误**

> 回放**必须**使用不复权价。
>
> 复权因子是用**未来的除权除息事件**倒推出来的。把前复权价喂给回放，
> 等于让用户在 2015 年的界面上看到 2016 年那次分红的信息。
> 这个未来函数不报错、不崩溃，只会让所有训练成绩系统性虚高。

实现：回放用不复权价，复权因子单列存储，仅在跨期收益率统计时使用。

**② 主力合约拼接 —— 两种方法结果不同，必须都提供**

| 方法 | 保持 | 适用 | 风险 |
|---|---|---|---|
| 价差平移法 | 绝对点数变动 | 按点数计盈亏 | 长历史 + 大 contango 时早期价格可能为负（已实现告警） |
| 比例法 | 百分比涨跌幅 | 收益率统计 | 改变绝对点数，按点数设的止损距离失真 |

拼接后的序列**不是任何一张真实合约的价格**，只适合形态训练与统计，
不能宣称「你在 2019 年能赚这么多」。这一点要写进产品文案。

**③ 涨跌停标记 —— 宁可漏标不可错标**

只有**一字板**（开=高=低=收且达到涨跌幅）才置位。
非一字板的涨停盘中是有成交的，错标会让模拟比现实更难。

**④ 停牌、数据校验**：成交量为零标记停牌；高低价矛盾、非正价格、时间倒序全部检出。

### 2.5 存储（待建）

- 服务端：ClickHouse 或 DuckDB + Parquet 分区（品种/年份）
- 客户端缓存：IndexedDB + 二进制分块（前提是授权允许）
- 分钟级 A 股全市场约 10 年 ≈ TB 级，需分层冷热存储

## 3. 系统架构

### 3.1 三条不可让步的架构约束

**① 未来数据永不进客户端**

原型的写法 `let replayFull = genCandles(180); let replayShown = 70;`
把全量数据放在客户端内存里，F12 即可看到答案。后果不是体验瑕疵：
双盲测试、成绩、排行榜、机构选拔全部作废，**而且数据一旦下发就收不回来**。

已实现（`src/replay.js`）：`GuardedBarSource` 以 `#private` 字段私有持有 K 线，
越过游标的任何读取**抛 `FutureDataError`** 而非返回数据。
测试枚举所有自有属性与原型方法，确认无一条能拿到完整数组。
生产环境中该类位于服务端，客户端只能拿到已推送的分片。

**② 撮合在服务端**

前端只提交交易意图，成交由服务端权威判定。否则成绩不可信，
排行榜与选拔无从谈起。已实现的 `src/matching.js` 是纯函数式的，
同一份代码可直接部署在服务端。

**③ 整场会话可确定性重放**

存 seed + 操作序列，不存结果。已实现 `replayFromLog()`：
从操作日志复现整场会话，逐字节比对最终权益与成交明细。
这是成绩可审计、可申诉的前提 —— 也是机构客户会问的第一个问题。

### 3.2 分层

```
┌─ 客户端 ─────────────────────────────────────┐
│  图表（KLineCharts）· 交易面板 · 报告呈现      │
│  只持有已揭晓的 K 线分片                       │
└───────────────┬──────────────────────────────┘
                │ 揭晓分片 ↓   交易意图 ↑
┌───────────────┴──── 服务端 ──────────────────┐
│  ReplaySession（游标权威）                    │
│  MatchingEngine（成交/成本/保证金/强平）        │
│  分析引擎 analyzeSession()                    │
│  LLM 翻译层（只吃结构化 JSON）                 │
├──────────────────────────────────────────────┤
│  行情库（ClickHouse/Parquet）· 用户档案 · 题库  │
└──────────────────────────────────────────────┘
```

### 3.3 图表：不要自己写

原型手写了 canvas 引擎（无时间轴、无成交量、无十字光标、MA 周期硬编码、
每帧全量重绘）。180 根没问题，真实回放是 10⁵–10⁷ 根，会直接死。

| 方案 | 许可 | 评价 |
|---|---|---|
| **KLineCharts** | MIT | 内置画线工具、指标体系、复权，最贴合 A 股/期货习惯。**推荐** |
| TradingView Lightweight Charts | Apache-2.0 | 性能极强体积小，画线工具需自建 |

自己写至少要三个月才能到这两个库的起跑线，而这三个月本该花在评估引擎上。

## 4. AI 能力技术栈

### 4.1 已实现

**① 反事实基准引擎**（`src/nulls.js` + `src/engine.js`）

五个条件随机化零模型。对照组复制用户的交易习惯（笔数、持仓时长分布、
多空比例、仓位分布），只随机化被检验的那一维度。用户的真实交易恰是该分布中的
一个样本点，**p 值精确，不依赖正态性假设**。

实测校准（真实 GOOG 日线，n=1500）：五个零模型一类错误率全部落在名义值的
二项 95% 区间内。详见 [`CALIBRATION.md`](CALIBRATION.md)。

**② 决策点归因** —— 不是另一个功能，就是同一套检验逐维度跑一遍的输出。

归因矩阵验证：造出只在单一维度作弊的合成交易者，四行**全部命中对角线**。
同时如实披露维度间存在结构性泄漏，只能给相对排序不能给可加分解。

**③ 行为偏差检测器**（`src/behavior.js`）

处置效应、报复性交易、止损纪律、动量偏好、保本平仓、交易摩擦。
**全部是确定性计算，没有一行涉及模型推测。**

> 开发中的一个教训：早期用 `Math.abs()` 分级，把「亏损持仓短于盈利持仓」
> 这一教科书级的好习惯误报成「处置效应·明显」。
> **一个把好行为标成毛病的指标，比没有这个指标更糟** —— 它会主动把用户往错误方向纠。
> 已改为单侧分级，并区分 problem / strength / profile 三类。

**④ LLM 翻译层契约**（`src/report.js`）

引擎输出结构化 JSON，模型拿不到 K 线、拿不到逐笔记录。
**幻觉不是靠提示词恳求消除的，是靠信息隔离让它在物理上无从发生。**
配套系统提示写了 9 条硬约束，包括「p 值不是你有能力的概率」
「维度归因只能引用多重比较校正后的 p 值」。

### 4.2 待建（按优先级）

**① IRT 自适应出题**（高优先级，产品留存的核心）

- 离线对全历史打行情状态标签（波动率分位、趋势强度、区间/趋势/突破/反转）。
  `src/bars.js` 的 `regimeLabels()` 已有规则版雏形，需升级为 HMM 或聚类。
- 用**项目反应理论(IRT) 或 Elo** 在每个状态维度上**分别**估计能力 θ 与置信区间。
- 出题采样「θ 最低 **且** 置信区间最宽」的维度，叠加 FSRS/SM-2 间隔重复。
- 产出「能力雷达随时间演进曲线」—— 这是最强的留存钩子。

原型里写的「像记忆卡一样哪弱练哪」是一句口号；上面这套才是实现。

**② 相似历史行情检索**（中优先级）

- 窗口 z-score 归一化 + 降采样 → 向量。起步用 shape descriptor / PIP + DTW 下界剪枝；
  进阶用对比学习 encoder（正样本 = 同片段的噪声增强）。
- 存 FAISS / pgvector。
- **关键设计：返回条件分布而非结论。**
  「命中 87 个相似片段，后 20 根 K 线上涨 54%，涨幅中位数 +0.8%，左尾 −4.2%（5% 分位）」
  —— 既有信息量，又不构成投资建议，合规上安全得多。

原型里这个功能是 6 条硬编码文案 + 6 段不同随机种子的假 K 线，「93% 匹配度」是写死的字符串。

**③ 形态自动识别 / 自然语言生成策略**（低优先级）

价值密度低于前两项，且容易滑向「荐股」的合规灰区。建议延后。

## 5. 合规边界

### 5.1 三条红线

**① 不得暗示收益**

原型文案「把实盘里几年的成长压缩进几周复盘」「陪你练成稳定的交易系统」
以及抄自 TEx 的「稳定盈利加速器」，**均已踩线**。
国内做投资者教育，暗示 training → 稳定盈利涉及是否需要投顾资质。

替代表述方向：强调「评估」「训练」「量化你的决策质量」，不承诺结果。

**② 不得荐股、不得给买卖建议**

AI 输出必须严格限定为**对用户历史行为的描述性归因**，
不含对未来价格的任何预测。这一条已经通过架构落实：
LLM 拿不到行情数据，它想荐股也没有素材。

相似行情检索必须输出**条件概率分布**而非方向结论。

**③ 不得编造用户评价**

原型里三条推荐语是编的（虽有免责标注）。demo 是拿去说服人的，
编的推荐语会让懂行的人对整份材料的可信度打折。删掉比留着强。

### 5.2 实盘选拔的合规量级

TEx 导流的「增上选拔」模式（模拟初赛 → 复赛 → 实盘赛 → 50% 盈利分成）
涉及资管资质，是**完全不同量级的合规问题**。

**建议**：不自己下场做资管，而是把评估与选拔系统**作为 SaaS 卖给持牌机构**。
这样既避开牌照问题，又切中 B 端真实需求（期货公司/私募确实需要低成本筛盘手）。

### 5.3 已落实的合规机制

- 每份报告强制携带 `caveats` 数组（样本量、不可加分解、不可外推、非投资建议）
- 样本量不足时结论强制为「无法判断」而非鼓励性评价（`MIN_TRADES_FOR_VERDICT = 20`）
- 全同方向/全同仓位时对应维度报「无从评估」，不把 beta 当 alpha 发给用户

## 7. 风险登记

| 风险 | 影响 | 缓解 |
|---|---|---|
| **数据再分发授权谈不下来** | 🔴 产品形态需重新设计 | 立项即启动询价；准备 BYOD 备选方案 |
| 维度归因的结构性泄漏被用户质疑 | 🟡 影响可信度 | 已在报告中强制披露，主动说比被指出好 |
| 样本量门槛导致早期用户体验差（前 20 笔什么结论都给不了） | 🟡 留存风险 | 用「还差 N 笔」做进度感；把日课设计成快速累积样本 |
| 用户不接受「你没跑赢随机」这种反馈 | 🟡 流失 | 这是产品的核心价值，不能妥协；但呈现方式要配训练路径 |
| 合规口径收紧 | 🟠 需下架部分功能 | 架构上 LLM 拿不到行情，天然不具备荐股能力 |
| 竞品跟进 | 🟢 低 | 校准体系与服务端权威架构不是加功能能追上的 |

## 8. 对现有原型的处置建议

现有 HTML 原型（`练盘 · AlphaGym`）视觉完成度高，但功能层是空的。建议：

**保留**：设计 token 体系、双主题、响应式布局、信息架构骨架。

**替换**：
- 手写 canvas 引擎 → KLineCharts
- `genCandles()` 随机游走 → 真实数据
