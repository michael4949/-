## 1. 产品定义

**卖什么：** 「睿衡 · 企业金融智能赋能中枢」，一个卖给银行的软件产品。14 个智能产品模块，覆盖企金客户经理从获客、洞察、财务诊断、行业研判、方案定价、授信、贷后、集团经营、陪练、沟通、合规、办公、增值方案到能力画像的全部工作。所有客户经理使用同一套功能。

**卖给谁：** 银行。首批目标是城商行、农商行与股份行分行，通过总行公司业务部与金融科技部联合立项。

**原型是什么：** 「一个分行公司业务团队的一天」。首页驾驶舱一眼看全局，六个真能跑的场景串成故事线：早会预警 → 尽调拜访与陪练 → 财报诊断 → 授信报告 → 集团方案 → 主管复盘。一条预警贯穿全天：彩晟商贸出事 → 晟禾集团受影响 → 宁桂精密授信前置条件 → 首页决策沙盘。

**它不是什么：** 不是培训系统，没有课时与认证；不是 688 个按钮的工具箱；不是聊天机器人；不是 CRM 或信贷系统的替代品；不是一段录像。

## 6. 智能陪练底座（P09）

按"陪练底座"产品形态设计，全部基于企金客户经理真实工作场景：

- **场景库（12 个）：** 首次拜访开场；尽调访谈中财务总监回避关键问题；异议处理"X 行 3.2% 还免担保"；续贷谈判客户要求降价；集团高管会谈（董事长）；审贷会答辩；贷后风险沟通（客户被执行后）；催收沟通；跨部门协调（与信审、风险经理）；客户投诉处理；供应链金融方案推介；跨境结汇产品推介。每个场景有难度、训练目标、对应产品功能。
- **虚拟客户：** 角色（财务总监、实控人、采购总监、董事长、办公室主任、信审经理）× 性格（强势、谨慎、敷衍、专业、情绪化）× 情绪值（随对话升降）。对练对手可绑定具体客户，用客户 360 与财报诊断结果生成人设。
- **对话引擎：** 本地剧本按异议类型分支（价格、担保、额度、期限、竞品、流程、回避、情绪），不少于 15 条分支加默认分支；正式版接行内模型。
- **教练条：** 实时识别异议类型、推荐行方审定话术（一键采用）、合规红线提醒（承诺性表述、评价同业、未核实政策）。
- **多维评估：** 10 维雷达（专业度、逻辑结构、说服力、需求挖掘、异议处理、产品匹配、合规性、共情倾听、成交推进、礼仪表达）+ 优势 / 待提升 / 合规三组标签 + 逐句点评（原话、点评、改进话术）+ 历史对比。
- **知识库与管理：** 行方审定话术库（开场、需求挖掘、异议、收尾）；主管任务下发、完成率与团队均分统计。评分只进本人能力画像。

10 维雷达（本人 vs 团队均值 vs 上季度）；七组标签：擅长行业、擅长产品、客户类型、沟通风格、风险偏好、合规记录、协作；12 个月十维成长曲线；成就徽章；本季度亮点（复核采纳率、预警处置时效、陪练得分）；AI 个性化建议并链接到对应产品；晋档建议差距条；系统生成的个人专业名片。个人明细默认只向本人展示，主管看团队聚合。

## 8. 信任与合规（保持 v2 不变的控制点）

数字可复算（前端确定性计算、公式与口径可展开、改数重算）；结论可溯源（点回报表坐标或原始信号）；责任可留痕（"复核确认"而非"签名"，AI 参与记录与 diff，目标态对接行内统一身份认证与不可篡改日志）；数据三类边界（公开 / 行内 / 授权，征信仅授信与贷后授权用途）；不替代内评、五级分类、审批与反洗钱系统；不做人脸、声纹、形象识别；监管对照表与三类责任划分放在"部署 · 数据 · 合规"页。

## 9. 技术与交付

- 技术栈：React 19 + Vite + TypeScript，`ruiheng/` 子目录；recharts 图表、lucide 图标、d3-delaunay 生成地图行政区；hash 路由，相对路径构建，可放任何静态目录或 U 盘 file:// 打开。
- 数据：`plan.json`（xlsx 层级）为唯一真源；`capabilities.json` 由脚本合并 5 个能力域的功能目录并校验 688 个能力点全覆盖；企业、人物、团队数据为固定种子的虚构数据。
- 模式：原型不发起任何网络请求；正式版 LLM 适配层三通道（回放 / 本机模型 / 行内网关）。
- 交付：本次提交为里程碑一（骨架 + 首页驾驶舱 + 六个场景 + 通用产品页 + 能力地图 + 画像 + 合规与合作页）。后续：内容润色、演示脚本步进控制条、移动回放版、白标构建、Playwright 冒烟。
