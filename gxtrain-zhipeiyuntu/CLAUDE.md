# CLAUDE.md — 智培云图 项目工作说明

给接手本仓库的 Claude Code 看。开工前通读本文件与 `docs/` 三份文档。

---

## 一句话说明

「智培云图」是为**南方电网广西电网有限责任公司人力资源部培训科**做的**人才培养数智平台高保真原型**，单文件 HTML 交付，用于现场演示。我方以「广州力航培训」名义对接培训科陈科长。

---

## 构建与运行

```bash
pnpm install
pnpm dev                                    # 本地开发
bash scripts/bundle-artifact.sh             # 若无此脚本，用下方 parcel 命令
npx parcel build index.html --dist-dir dist --no-source-maps
npx html-inline -i dist/index.html -o bundle.html
```

产物 `bundle.html`（约 1.4MB，含 21 幅数字人形象图的内嵌数据），双击即可在任意电脑打开，无需联网、无需服务端。

技术栈：React 19 + TypeScript + Tailwind 3 + Vite（开发）+ Parcel 单文件打包。`pnpm lint` 使用 oxlint，`npx tsc -p tsconfig.app.json --noEmit` 做类型检查（`src/components/ui/**` 的报错可忽略）。
`src/components/ui/**` 是 shadcn 脚手架自带，本项目基本未用，可忽略。

七个模块在 `data.ts` 的 `NODES` 里定义（id / 标题 / 一句话定位 / 三个指标 / 二级功能列表），
`App.tsx` 的 `SHORT` 定义菜单短标题。新增模块要同时改这两处 + 加 module 组件 + 在 `scenes.tsx` 补一条动效带。

### 两个已成型的深化范式

- **知识资产中枢**：八个一级功能（总览驾驶舱 / 资产目录 / 语义检索 / 智能入库 / 专家经验萃取 / 知识图谱 / 规程版本与影响 / 质量与权限），每个一级页都可下钻到二级、三级（目录 → 条目详情 → 引用清单 / 规程原文 / 版本对比；入库 → 批次 → 条目审核；版本库 → 版本详情 → 同步任务单；质量 → 问题清单 → 条目）。路由栈在 `hub/nav.tsx`，新增页面只需扩展 `Route` 联合类型、`labelOf` 与 `modules/Hub.tsx` 的 `render`。其余模块的深化按同一范式做。
- **AI 智能陪练**：参照客户提供的「小瓦特·练」底座整体重做，人物形象全部保留，业务口径换成广西电网（南宁地调 / 广西中调 / 110kV 仿真站 / 培训三线 1163）。八个页面 + 公司看板，三种视角（学员 / 班组长 / 培训科）。

### 使用对象口径

平台使用对象是全部 28 个一级单位（17 个本部职能部门、6 个直属机构、14 个地市局、40 家县企、3 家产业公司），人力资源部自身也在其中。凡是涉及"覆盖范围""身份""单位"的地方都从 `src/units.ts` 取数，不要再写死"14 个地市局"。

## 硬性规则（客户已多轮明确，违反必须返工）

### 交互与视觉

1. **导航只能是顶部横版菜单 + 二级下拉**。滚轮缩放画布、中枢星盘、角色入口、分幕大屏、指令中心、培养主线、人才地图、双栏对照，这些都已被明确否决，不要再提。
2. **背景实景照片必须真实呈现**，不得整体压白遮罩把照片遮没。只允许靠局部处理保证文字清晰：标题区径向柔光、天空区顶部渐隐、底部压深。
3. **动效必须与页面结构和数据本身融合**。"在页面上漂几个图标"已被明确批评，禁止再用。
4. **动效要贯穿每一级页面**，不能只有首页有。
5. **原型中不得出现任何介绍式、讲解员式内容**。不要"交付物与报价口径""一期范围"徽标、"演示环境"标注、"点击××可下钻"这类导览提示。界面上每个字都应当是客户员工日常真实使用的系统里会出现的字。

### 文案表达（贯穿所有对话与所有交付物）

6. **坚决不用"不是……而是……""不……而……"这类先否定再肯定的句式**，只保留肯定部分，直接正面陈述。
7. 不用"手术""骨架""刀"，换中性词（调整、重构、框架）。
8. 不用"门禁"，改"关口""准入""把关"。
9. 命题与标题用正向表述（例："经验可传承"），避免"带不走"这类负面词。
10. 方案名称要有格调，不能把业务内容平铺成标题。
11. 面向客户高层的短消息与文案不用俚俗口语腔（"说白了""新玩法""新尺子"），用平实专业的陈述。
12. 不用自我问责 / 自证式表述（"保兑现""保守底线""参数可逐项质证复核"），改正向表述。
13. 报价类交付：不给区间价与分档价，直接给底价一个数；以功能模块为计价单位；报价表任何位置不得出现"人天"口径，包括边界条款里的"约 X 人天"，一律折算为金额。
14. 客户正式文档中不得出现写给我方看的过程性内容（版本对比、改了什么、修订说明、内部话术）。本 CLAUDE.md 与 docs/ 属于内部材料，不受此限。
