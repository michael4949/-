# AI决策 · 指标 归因 方案 审批

老板的经营决策台，坐在前面几个模块之上：**指标**从 AI CFO、AI ERP、AI获客、AI人力官、AI法务 的同一个世界里取，31 个节点按公式逐月算出并与预算或上期比给红黄绿；**归因**用连环替代法把指标变动拆到驱动因子，各因子贡献之和等于变动，证据卡指回对应模块；**方案**按根因给两到三个可调参数的方案，预演 12 个月走势、净效益与现金影响并按风险系数推荐；**审批**由规则生成三位会签意见，总经理终批后形成有编号的决议，执行节点与跟踪目标进台账，下一期按目标线复盘。纯规则、无 LLM、断网可用；发起审批、批准 / 驳回、节点更新都写进同一份数据副本。

## 引擎 `core/decide.js`

| 函数 | 作用 |
|---|---|
| `run(data, lib, opt)` | 一次算全：指标树、归因、决议台账、KPI、月报；`opt = { metric, basis }` 决定返回里 attribution 算哪个指标、比哪个基期，缺省 `profit` / `prev`（经营利润较上期），原型正是靠这个第三参数切换归因；屏上选中的那一档也从这里进来——`opt.cause`（根因）、`opt.option`（方案 key）、`opt.params`（按方案 key 分组，形如 `{ A: { hires: 5 } }`），认得的原样收进返回里的 `selection` 交给对话用，认不得的丢掉，一个都不传就不出 `selection` |
| `tree(d, lib)` | 按 `data/metric-tree.json` 的公式算全树：sum（带符号求和）、product（乘积）、leaf（序列或表达式）；每节点给本期、上期、前三月均值、预算、偏差与状态 |
| `attribute(d, lib, metric, basis)` | 连环替代法：按公式树逐层替换，乘法节点按 收入 → 毛利率 的顺序，加法节点直接取差；基期可选上期或前三月均值（复合节点由叶子基期值重算）；含一次性项的叶子（`facts.oneOff`）剔除后再判主因；可归因指标只有指标树 `attributable` 列出的 6 个：经营利润 `profit`、毛利 `grossProfit`、收入 `rev`、毛利率 `gm`、期间费用 `opex`、现金周期 `ccc` |
| `evidence(d, lib, factor, direction)` | 因子到证据卡：来自哪个模块、哪一屏、说明文本（占位符由 facts 填充） |
| `options(d, lib, causeId)` · `simulate(d, lib, causeId, optionKey, params)` · `simulateAll(d, lib, causeId, paramsByKey)` | 方案库按根因取方案（叶子没有则沿指标树向上回退）；参数作用在驱动节点上按 pct / pt / add / days 生效并按见效期与爬坡线性到位；12 个月利润、毛利率、现金周期、准时率走势；净效益 = 12 个月利润增量 − 投入；现金影响另加营运资金释放；推荐 = 净效益 × 风险系数最高者；`simulateAll` 的第四个形参按方案 key 分组，形如 `{ A: { ... }, B: { ... } }`，不是扁平的参数对象 |
| `submit(d, lib, causeId, optionKey, params)` · `approve(d, lib, approvalId, comment)` · `reject(d, lib, approvalId, comment)` | 发起审批单（submit 传根因、方案 key 与参数五个形参，不直接传方案对象；三位会签按规则给同意 / 有条件同意 / 反对）；批准形成决议（执行节点按天数排期、跟踪目标取预演前 6 个月）；驳回留意见。三者只对 status 为 `pending` 的单子生效，否则原样返回数据副本 |
| `setMilestone(data, decisionId, index, status)` · `decisions(d, lib)` | `setMilestone` 推进节点状态，是内核里唯一不接收 lib 的写操作，第二个形参直接是决议编号、第三个是节点下标；`decisions` 要传 lib，给出进度、逾期、跟踪目标与实际的偏差、复盘 |
| `screens()` | 本 skill 的六个环节登记：`[{key,label}]`，顺序即原型标签顺序（接入 / 决策驾驶舱 / 指标归因 / 方案预演 / 审批 / 执行与复盘） |
| `brief(step, data, lib, result?)` | 进某一屏的开场发现：一句从 `run()` 结果里算出来的话，字符串或 `{text, blocks?, act?, ref?}`；未知屏返回 null |
| `suggest(step, data, lib, result?)` | 该屏的快捷问句 3–4 条，每条都能被 `ask` 答上 |
| `ask(question, step, data, lib, result?)` | 问答：返回 `{text, blocks?, act?, ref?}`，答不上返回 null（交平台兜底，不编数） |
| `ingest(doc, step, data, lib, result?)` | 文档摄入：入参是 `../_shared/docparse.js` 的输出，返回 `{text, blocks?, act?, data?}`；写业务数据时 `data` 是新副本，入参不动 |
| `kpi / report`（模块内私有，由 run 返回，不单独导出） | 指标状态计数、主因、待批与执行中；决策月报含风险指标、归因、审批、执行、复盘、处置与待办。外部从 `run()` 返回值的 `.kpi` / `.report` 取 |

## 口径

- 指标数字直接取各模块样本：收入、毛利率、费用、应收、存货、应付来自 AI CFO 账套；准时交付率、延期单、瓶颈负荷来自 AI ERP 排程结果；新客成交、线索、转化率来自 AI获客；在编、离职率、加班超限、合规影响来自 AI人力官；高风险合同来自 AI法务。各模块没有月度历史的指标，按当前值向前铺序列，末月与对应模块屏上的数一致。
- 直接人工 = 生产工资与社保 × 直接人工比例（制造 78%、贸易 50%、服务 78%），其余为间接人工计入制造费用。
- 归因只做连环替代法，不做统计回归，不接大模型；可归因的只有指标树 `attributable` 标出的 6 个指标，下钻到非可归因节点时回退到所属组的根指标；法律与合规口径沿用对应模块。
- 联系人只出现职务；决议与审批单只出现编号；费用一律标预计。

## 对话与文档摄入

`screens / brief / suggest / ask / ingest` 五个导出与六屏一一对应，纯函数：只认入参，不碰 DOM、window、时钟与随机数，同一组入参永远同一份输出。第四个形参 `result` 是 `run(data, lib, opt)` 的结果，可选——原型把按当前指标与基期算好的结果传进来，不传就按 `profit` / `prev` 自己算一次。回答里的数字全部从结果里取，答不上返回 null。

**屏上选中的那一档在契约里**：平台调 `run` 时把当前选的根因 / 方案 / 参数放进 `opt`（见上表），内核收进 `result.selection`，拟稿、预演、会签预判、净效益与发起审批 / 批准的 `input` 全按选中的那一档算——对话给的数与屏上卡片、滑杆上的数一致，发起审批落的也是屏上选的那个方案。`selection` 里的参数按方案 key 分组（`{ A: { hires: 5 } }`），只给一层、没分组时按 `option` 选中的那个方案收；逐项对方案库的定义校验，认数字、超出上下限的收回区间内；根因方案库认不得、方案 key 不在方案里、参数不是数就丢掉那一项，回退到推荐的那一档与方案默认参数。没有传 `result`（或传了不带 `selection` 的 `result`）时也走推荐档。因子取主因（没有主因取贡献居前的一个），决议按 复盘未达标 → 有逾期节点 → 执行中 → 台账排在前面的一项 取，与执行屏默认选中的那一项一致；平台自己的其余选中态靠 `act` 回写。

| 屏 | 认得的问法 | 回答里给的数 |
|---|---|---|
| 接入 | 亮红 / 红灯 / 超容差 / 容差外 / 哪几项 / 风险指标；指标节点 / 指标树 / 几个节点 / 多少指标；同步 / 什么时候 / 取数 / 数据源 / 几个模块 | 亮红与贴着容差的项数、排前面的三项与本期值和偏差；31 个节点按六组拆、容差外项数与落在哪一组；来源数、同步时刻、合计条数与直连数 |
| 决策驾驶舱 | 决议 / 台账 / 几项决议；待批 / 审批单 / 几单；打开 / 抽屉 / 明细 / 全组 / 组里 / 还有哪些；积分 / 多少钱 / 收费 | 决议项数与执行中、已完成、逾期节点数；待终批的单号、方案名与净效益，没有就报拟稿；那一组的指标数与容差外数；进一次驾驶舱扣的积分 |
| 指标归因 | 为什么掉 / 为什么降 / 掉了 / 降了 / 原因 / 怎么回事（点名因子就答那一个）；主因 / 怎么定的 / 根因 / 判断依据；证据 / 在哪看 / 凭什么 / 哪来的 | 指标基期到本期的变动与不利因子数、贡献前几名；主因的因子变动、贡献、占变动比与剔除一次性后的判法；该因子的证据卡张数、来自哪个模块与说明 |
| 方案预演 | 方案 / 怎么办 / 建议 / 下一步 / 对策 / 差在哪 / 选哪个；增员 / 加人 / 调价 / 降幅 / 比例 / 参数 / 改成（带数字就按那个数重算，`3.5` 这样的小数一样认，落进 `act` 的也是这个数；问的数就是当前值时只报这一档的账，不说改过）；见效 / 多久 / 几个月 | 各方案的净效益、投入、见效月份与推荐哪一个；参数从原值调到新值后的净效益、期末毛利率与现金影响；见效月份、执行节点数、责任与 12 个月后的毛利率和准时率 |
| 审批 | 会签 / 反对 / 意见 / 谁同意 / 有条件；净效益 / 怎么算 / 算出来；批了会 / 批准后 / 批完；发起审批 / 提交审批 / 上会；批准 / 批了 / 通过它 | 三位会签人的意见与原话；净效益 = 12 个月利润增量 − 一次性投入，连同现金影响；批准后的节点排期、末节点、责任与跟踪指标（只讲不落单）；发起与终批各自会发生什么 |

任一屏还认四种点名：指标名给本期、上期、预算或近三月均值与状态；因子名给因子变动、贡献与来源模块；`D-年月-序号` 给决议的状态、进度、责任与投入；`A-年月-序号` 给审批单的状态、净效益与三位会签意见。

|---|---|
| `{type:'goto', step}` | 切到那一屏（六屏之外的 key 不处理，交平台兜底） |

| `{type:'open', panel, ref}` | `group` 开某一组的指标明细抽屉（ref 是组 key 或组根节点 id）、`evidence` 进归因屏选中该因子并高亮证据卡、`review` 进执行屏选中该决议并高亮复盘、`report` 开决策月报全文抽屉 |

| `{type:'set', path, value}` | `metric` 换归因指标（非可归因节点按所属组回退到组根，并把该节点选成因子）、`factor` 选中某个因子、`basis` 换基期（`prev` / `avg3`）、`params.<根因>.<方案 key>.<参数 key>` 改方案参数后重算 |

**ingest 认的文档与写回**（入参一律是 `../_shared/docparse.js` 的输出）

| 文档 | 判定 | 结果 |
|---|---|---|
| PPT | 经营回顾 | 报页数与首页标题，从正文抠「指标 数值」对与指标树同名节点对账，报文档值、本期值与差；`data` 里按页数记一条导入批次与处置日志，对上的口径按所属组写成 `docTargets`（驾驶舱瓦片上的目标） |
| Excel，表头有科目名称与期末余额 | 科目余额表 | 借贷合计与差额是否对平，应收账款期末折回款天数并与指标树里的回款天数比，列出存货、应付、银行存款期末；`data` 里按行数记一条导入批次 |
| Excel，其余 | 非科目口径 | 报表数、行数、列名与数额居前的一笔，说明对账要科目名称与期末余额两列；`data` 里按行数记一条导入批次 |
| Word / PDF / 文本，读得到金额、账期、违约条款或指标数值 | 合同或经营文本 | 金额与本期合规敞口、高风险合同数比，账期与回款天数比，正文对上的指标口径一并写成目标；`data` 里按段数记一条导入批次。中文写法（合同金额 / 账期 / 违约金，金额不写「万元 / 元」的按元算）先认，认不到再认英文写法（`Amount` / `Contract Value` / `Total` + `CNY`、`Payment Terms` / `Net 60 days`、`Penalty` / `Late fee`） |
| Word / PDF / 文本，三样都读不到 | 无口径 | 说明正文里没读到金额、账期条款或能对上指标树的数值，六屏这一期不动数，给开头一段；不写数据 |
| 邮件 | 往来邮件 | 报发件、主题、日期与附件数（发件只留职务那一段，邮箱地址不进回答）；正文对上指标口径的把目标写到对应组，对不上的说明不动数 |

写数据的那一类返回 `{text, blocks, ref, data}`：`data` 是新副本（入参不动，照 `ensure` 先出副本再改），平台把它存回会话状态就算并完了。**写回只有 `data` 这一条路，`ingest` 不返回 `act`** —— `act` 里的 `apply` 不许指回这次调用的动作自己（通用层叫 `ingest-document`、`family` 是 `ingest`），指了也会被合规平台按未知动作丢掉。数据源里只保留最近一份文档的 `doc-import` 批次，同一份文档重复导入，处置日志也只留一条。

## 原型流程（六屏）

接入 → 决策驾驶舱（北极星与六组指标树、红黄绿、本期偏差榜、待批与执行中）→ 指标归因（选指标与基期，瀑布图与因子表，证据卡跳转对应模块，锁定根因）→ 方案预演（两到三个方案调参数、12 个月走势对比、AI 推荐、发起审批）→ 审批（审批单、会签意见、总经理批准 / 驳回、决议编号）→ 执行与复盘（决议台账、节点推进、目标线与实际线、复盘结论、决策月报发微信）。进入驾驶舱扣 100 积分，一次。
