# 场景与痛点库 · 数据规格

每个行业大类一个文件：`<sector>.json`，结构与 `mfg.json` 完全一致。**先完整读一遍 `mfg.json`，按它的字段、颗粒度与文风写。**

```
{ "sector": "<key>", "sectorName": "<中文名>", "pains": [16 条], "scenes": [13 条] }
```

## pains（16 条，四组各 4 条）

| 字段 | 要求 |
|---|---|
| `id` | `<sector>-p01` 到 `-p16`，按顺序 |
| `group` | `sales` 获客与销售 / `deliver` 交付与生产 / `cost` 成本与财务 / `org` 组织与管理，各 4 条，按此顺序排列 |
| `tag` | 2–5 字标签，本文件内唯一，场景靠它匹配 |
| `text` | 一句话，老板自己会说出口的原话，18–28 字，写现象不写评价 |
| `hint` | 一句补充，说明这个现象背后的机制，10–20 字 |

## scenes（13 条）

| 字段 | 要求 |
|---|---|
| `id` | `<sector>-s01` 到 `-s13` |
| `name` | 场景名，4–12 字，动宾结构，是一件具体的事 |
| `stage` | 所在业务环节，3–6 字 |
| `user` | 谁用它，具体到岗位 |
| `replaces` | 替代掉的具体工作，带时间量词，如「每天上午手工核对交期的两小时」 |
| `painTags` | 1–2 个，必须是本文件 pains 里出现过的 tag |
| `dataDeps` | 依赖的业务系统，取值只能是 `erp` `finance` `crm` `oa` `mes` `shop` `hr`；不依赖任何系统写 `[]` |
| `dataList` | 所需数据清单 3 项，具体到表名或记录名 |
| `value` | 价值 1–5 整数 |
| `cycle` | 见效速度 1–5 整数，5 = 最快见效 |
| `barrier` | 实施门槛 1–5 整数，5 = 门槛最高 |
| `cost` | 投入档，只能是 `零` `轻` `中` `重` |
| `weeks` | 上线周数，2–20 的整数，与 cost 相称 |
| `module` | 对应模块，只能取：`AI获客` `AI人力官` `AI CFO` `AI法务` `AI流程提效` `AI决策` `AI ERP` `AI软件开发` |
| `metric` | 预期指标，带数字区间，如「交期达成率提升 8–12 个百分点」 |
| `firstStep` | 第一步，一件今天就能安排下去的事 |
| `precondition` | 前置条件一句，写清楚缺什么先补什么 |
| `roiBasis` | 收益折算口径一句，「按……折算」 |

## 硬约束

1. **标签闭环**：16 个 pain tag 每个都要被至少一个场景引用；场景的 painTags 不得出现 pains 里没有的标签。
2. **覆盖度**：13 个场景至少覆盖 5 个不同的 `module`，至少 3 个场景 `dataDeps` 为 `[]`（零数据门槛，可当天起步），`cost` 四档都要出现，`barrier` 要有 1–2 分的也要有 4–5 分的。
3. **行业真实**：场景要是这个行业真实存在的业务动作，覆盖该大类下的细分行业（见下方清单）。不写放之四海皆准的通用场景。
4. **表述禁忌**（违反即返工）：
   - 不用「不是……而是……」这类先否定再肯定的句式
   - 不出现「手术」「骨架」「刀」「裁员」「减员」
   - 不出现任何数据源或软件厂商名称，统一写「财务软件」「业务系统」
   - 不用「最」「第一」「唯一」「保证」「承诺」「100%」这类绝对化用语
   - 只写肯定句与做法，不写评价
5. **数字用半角，范围用 en dash（–），中英文之间留空格**，与 mfg.json 一致。
6. 输出为合法 JSON，缩进 2 空格，不带注释。
