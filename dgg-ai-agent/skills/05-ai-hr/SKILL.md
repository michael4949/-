# AI人力官 · JD 简历 面试 合规 成本

接企业自己的花名册、工资表、考勤、社保申报表和招聘渠道导入的简历，把「要招人 → 人到岗 → 用工不踩线 → 成本看得清」串成一个工作台：**JD**（按岗位库与企业信息拼装，两版）、**简历**（硬门槛 + 加权匹配打分，逐条解释）、**面试**（结构化题库、四维评分、录用建议与 offer 定薪）、**合规**（12 条规则逐人核对，给涉及人数、影响金额与整改动作）、**成本**（用工成本结构、人效、12 个月三方案编制对比）。纯规则、无 LLM、断网可用；发布、初筛、面试、评分、offer、整改、采纳方案都写进同一份数据副本，各屏按副本重算。

## 引擎 `core/hr.js`

| 函数 | 作用 |
|---|---|
| `ensure(raw)` | 规范化数据副本：补齐 `resolved / log / plan`、候选人阶段与评分 / offer / 技能证书字段、需求单状态。所有写回动作内部先调用它，外部接入与原型载入样本也先调用一次，是写回与接入的入口 |
| `run(data, lib)` | 一次算全：组织盘点、需求单与 JD、候选人打分、合规、日历、成本、三方案、KPI、月报 |
| `org(d, lib)` | 部门 × 编制 × 在编、司龄 / 年龄 / 学历结构、近 12 个月离职率与原因、派遣占比、同岗位工资中位、人均产值 |
| `jd(d, needId, lib, variant)` | 从 `data/jd-blocks.json` 与岗位库拼装：公司与岗位、职责、要求、薪酬福利（薪酬带按地区系数与企业工资指数换算）、地点时间；`poster` 为内推海报版 |
| `band(d, jobKey, lib)` | 薪酬带换算：岗位库基准带 × 地区系数 × 企业工资指数，按百元取整；JD、offer 定薪、三方案取的是同一个带 |
| `screenOne / candidates` | 硬门槛（学历、经验、必备技能、证书、到岗期限）不满足记 D；匹配分 = 技能 35% + 经验 20% + 行业 15% + 稳定性 15% + 薪酬 10% + 通勤 5%；A ≥ 82 / B ≥ 66；解释给「看了哪些字段 / 判断依据」 |
| `pass / reject / schedule / score / offer / publish` | 写回动作：初筛、淘汰、安排面试（进日历）、录入四维评分、发 offer、发布 JD |
| `interviewKit / interviewResult` | 题库：专业题在岗位库，协作 / 稳定性 / 价值观题按岗位族；评分 1–5 按岗位族权重加权，≥ 4.0 建议录用、≥ 3.2 备选；定薪 = 薪酬带内、不低于期望、按评分在内部同岗位中位上浮或下调 |
| `compliance / resolve` | 12 条规则：未签合同、合同到期、试用期超限、竞业无补偿、社保基数、加班超 36 小时、年假、派遣比例、残疾人比例、三期合同顺延、工伤参保、高温津贴；`fix` 类整改直接写回花名册，`plan` 类进台账 |
| `calendar` | 90 天人事日历：合同到期、试用期届满、哺乳期结束、到岗期限、面试，按 13 周分格 |
| `cost(d, lib)` | 月成本 = 工资 + 社保 + 公积金 + 福利；年化加招聘、培训、流失成本；成本结构、占收入比、人均成本与人均产值。签名上还留着第三个形参（组织盘点结果），函数体已不再使用，外部调用可省略 |
| `simulate(d, lib, C, comp)` | 三方案 12 个月：A 按需求单招满、B 招满并把社保基数调到位、C 自然流失不补加内部转岗。要先拿到 `cost()` 与 `compliance()` 的返回值当 `C` / `comp` 才能调用，对外取三方案走 `run().sim` |
| `adoptPlan(raw, key, lib)` | 写回采纳的编制方案，成本屏与月报按采纳结果重算 |
| `screens()` | 六个环节登记 `[{ key, label }]`：connect / board / recruit / interview / compliance / cost |
| `brief(step, data, lib, result?)` | 这一屏的开场发现，返回字符串（或 `{text, blocks?, act?, ref?}`），不认的屏、以及算不出一句整话的空态返回 null |
| `suggest(step, data, lib, result?)` | 这一屏的快捷问句 2–4 条，条条都能被 `ask` 答上 |
| `ask(question, step, data, lib, result?)` | 问答：返回 `{text, blocks?, act?, ref?}`，认不出的问法返回 null 交给平台兜底 |
| `ingest(doc, step, data, lib, result?)` | 文档摄入：返回 `{text, blocks?, act?, data?}`，写回业务数据时 `data` 是新副本，入参不动 |

后五个是对话能力，`result` 是 `run(data, lib)` 的结果，传了就用、不传自己算一次；`brief / ask / ingest` 还认入参 `data` 上的可选字段 `focus`（选中态，见下）。与其余函数一样是纯函数：不碰 DOM、window、网络、时钟与随机数，同一组入参永远得到同一份输出。`planNote(result, plan)` 与 `fmtN / fmtW` 同属取数用的文本工具，不计入动作。

## 口径

- 制造主样本沿用杭州锐合精密五金：168 人、月工资总额与社保基数与 AI CFO 账套逐月一致，H05 社保基数的年敞口与 AI CFO 风险 K10 是同一个数；在招的 CNC 操作工对应 AI ERP 的 CNC 瓶颈，华南销售对应 AI法务 的华南子公司与 AI获客 的华南客户；技术岗竞业无补偿对应 AI法务 的劳动合同模板问题。
- 简历只审预置的结构化简历，不上传解析；招聘来源只有企业自有渠道加「招聘网站导入」，不出现厂商名。
- 员工与候选人只出现工号 / 编号与岗位，不出现姓名；面试官只出现职务。
- 法律依据只写到法律名称一层；费用一律标预计。

## 原型流程（六屏）

接入 → 人力驾驶舱（在编与缺编、离职率、人效、成本占比、合规、部门盘点、招聘进度、人员结构）→ 招聘 · JD 与简历（需求单、JD 两版发布、候选人打分表、逐条解释、初筛 / 淘汰 / 安排面试）→ 面试与录用（面试安排、题库与评分表、四维雷达、录用建议、offer 定薪）→ 用工合规（规则表、涉及员工、整改写回、90 天人事日历）→ 成本与编制（成本结构、12 个月三方案对比与采纳、月报发微信）。进入驾驶舱扣 30 积分，一次。

## 对话与文档摄入

`brief / suggest / ask / ingest` 与六屏一一对应，回答里的数字全部从 `run()` 的结果里取，答不上返回 null，不编数。

**选中态 `data.focus`**：用户此刻在屏上选的是哪一条，宿主挂在入参 `data` 的可选字段 `focus` 上交给内核，回答就跟着那一条走。

| 字段 | 是谁 | 取不到时的默认 |
|---|---|---|
| `need` | 当前需求单 id | 头一张需求单 |
| `cand` | 招聘屏选中的候选人 id | 该需求单下未淘汰且匹配分排在前面的一位 |
| `icand` | 面试屏选中的候选人 id | 面试安排里按面试日期排在前面的一位 |
| `plan` | 对比中的编制方案 `A / B / C` | `data.plan \|\| 'B'` |
| `jdVariant` | JD 版本 `site / poster` | 需求单已发布的版本，没发布过取 `site` |
| `who` | 月报收件人下标 0–2 | 0（总经理） |

字段可以只给一部分，给了但对不上号（比如 id 在数据里不存在）一律退回默认。`focus` 只在调用时挂一次，`ensure()` 原样带着走，不参与任何计算，也不写进业务数据；确定性不受影响：同一组入参（含同一个 `focus`）永远得到同一份输出。要从入参 `data` 读，不要从 `result.data` 读——传了 `result` 内核就不会再跑一次 `run()`，`result` 里那份未必是这一次挂的。合规「先处理哪一条」是按严重度与影响排出来的结论，不跟选中态走，始终取待处理里排在前面的一条。

**空态**（宿主的数据包不一定每样都有，内核一律不抛异常）：没有需求单时 `brief('recruit')` 返回 null，招聘屏的问法答「当前没有在招需求单…」；需求单还没有候选人时开场发现只讲需求单（「候选 0 人，简历进来后出打分」），A 级 / 硬条件 / 薪酬带 / 下一步各给不列名单的那一版；合规待处理清零时不再拿已处置的规则当头号问题，开场发现与「先处理哪一条」改口「N 条规则核对完，无待处理项」；社保基数与工资同口径时接入屏不再说「要补」；简历传进来但没有需求单时只报读到的字段，不打分也不入池。

| 屏 | 认得的问法 | 回答里给的数 |
|---|---|---|
| 接入 | 数据源 / 直连 / 同步 / 导入；社保、基数、差多少；能力、开通、能做；多少人、在编、编制 | 来源表与直连数、基数与工资合计及差额、已开通 4 项、在编 / 编制 / 缺编 / 部门数 |
| 人力驾驶舱 | 缺编、哪个部门；离职、流失；加班、超限、工时；先处理哪一项；在招、招聘、需求单；成本、占收入、人均 | 缺编分布、离职率与原因前三、加班超限人数与加班费敞口、待处理里排在前面的规则、需求单表、成本占收入与人均产值 |
| 招聘 · JD 与简历 | A 级、筛出；不满足、硬条件；薪酬带、期望；怎么打分；JD；下一步 | A 级名单与分数、卡在哪条硬门槛、薪酬带与期望中位、六项权重、JD 字数与发布状态、当前候选人的建议动作 |
| 面试与录用 | 定薪；谁还没评分；为什么是这个分；发 offer；题库 | 薪酬带 / 内部中位 / 期望 / 建议定薪、待评名单与面试日期、四维分与权重、录用建议、题量与面试官 |
| 用工合规 | 先处理哪一条；调基数、整改、执行；影响、金额；到期、日历；派遣 | 规则涉及人数与影响预计、H05 写回人数与敞口、待处理合计与前三、30 天内到期分类、派遣占比与上限 |
| 成本与编制 | 方案 A / B / C；采纳；逐月、明细；社保基数补齐；人均、成本结构；月报 | 12 个月预计与较现状差额、期末在编与缺编、每月社保差额与年敞口、人均成本与年化结构、月报段数 |

任一屏还认「H01–H12」与「C-年月-序号」两种点名：前者给规则状态、涉及人数、影响预计、法律依据与口径，后者给匹配分、学历经验、期望与建议动作。

**act 在本模块的落法**（平台只实现子集也能跑，不认识的 type 静默忽略）

| act | 本模块 |
|---|---|
| `{type:'goto', step}` | 切到那一屏；切到招聘屏时清掉候选人筛选 |
| `{type:'focus', ref}` | 按 `data-ref` 高亮：部门行、候选人行、规则行、需求单块、面试安排项、涉及员工行 |
| `{type:'open', panel, ref}` | `rule` 选中规则并进合规屏、`candidate` 选中候选人并进招聘屏、`jd` 开 JD 全文、`kit` 开题库与锚点、`months` 开方案逐月明细、`report` 开人力月报、`doc` 开文档解析抽屉（抽屉内容在 act 的 `blocks` 里，同一套块型） |
| `{type:'apply', action, input}` | `resolve-compliance{rule}` 合规整改、`make-offer{id,salary}` 发 offer、`adopt-plan{key}` 采纳方案。**动作名一律用通用包 `manifest.actions` 里的动作名**（不是内核导出名 `resolve / offer / adoptPlan`）—— SPEC §12：平台执行 `apply` 前会校验「在清单里 · family 是 core · 不是当前动作自己」，三条任一不过就整条忽略 |
| `{type:'set', path, value}` | `filter` 切候选人筛选（A / new / interview / offer / fail）、`plan` 切对比中的方案 |

**ingest 认的文档与写回**（入参一律是 `skills/_shared/docparse.js` 的输出）

| 文档 | 判定 | 结果 |
|---|---|---|
| Word / PDF / 文本，命中两个以上简历词 | 简历 | 按 `focus.need` 指的那张需求单（没给就取头一张）算匹配分与硬门槛，缺的项按本批候选中位代入；`data` 里新增一条候选人与一条「简历入池」日志。没有需求单时只报读到的学历 / 年限 / 技能 / 期望，不打分也不写数据 |
| Word / PDF / 文本，其余 | 合同文本 | 按劳动合同六项必备条款逐条核对，读条款数、金额与日期，给出能否按劳动合同继续核对的判定；只开抽屉，不写数据。抬头按 `doc.kind` 写 Word / PDF / 文本 |
| Excel | 花名册 / 工资表 | 比对逐人核对要的六列，命中三列以上可进核对；只开抽屉，不写数据 |
| PPT | 经营回顾 | 读到「收入 … 万元」就把 `profile.revenue12` 改成文档口径，`data` 里加一条「收入口径改按文档」日志，六屏按新口径重算 |
| 邮件 | 人事事项 | 读发件、主题、日期、附件数与金额，判断是否命中入转调离 / 工时 / 假期 / 社保 / 薪酬；只开抽屉，不写数据 |

写数据的两类返回 `{text, blocks, ref?, data, act}`：`data` 是新副本（入参不动），平台按 `mutatesPath: "data"` 取走存回会话状态。`act` **不再是**指回自己的 `apply`（SPEC §12 禁止）：简历入池给 `{type:'focus', ref, step:'recruit'}`，PPT 改收入口径给 `{type:'goto', step:'cost'}`。
