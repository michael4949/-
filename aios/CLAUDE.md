# 顶呱呱AI操作系统 · 岗位智能体设计标准（必须遵守）

> 本标准来自「销冠AI助手」打磨过程中用户认可的要求，是后续所有岗位智能体
> （财务、HR、客服、项目交付、投标、研发…）的强制践行标准。每次做新模块前先读这里。

## 八条铁律

1. **真实业务流程驱动，按本岗位自身形态组织**
   先理解该岗位在企业中的真实日常工作流与场景，按它**自己的形态**来（销售=线索漏斗/分诊；
   财务=职能线循环）。**不照抄其它模块的流程和表现形式**；不做"管理后台/仪表盘"式的旁观视角。

2. **覆盖完整业务流程**
   覆盖该岗位**全流程的所有关键环节**，不能只做一个切片。

3. **每个环节都必须可真交互（没有"只能看"的页面）**
   不允许任何环节只是展示。每个环节都要能操作，且操作后有 **AI 真在干活的可见结果**。

4. **交互要深、要有智能性（能"激发老板购买欲望"）**
   严禁"只有几个按钮"或"点一下弹一段预写文字（单击 reveal）"这种浅层交互。要做到至少其一：
   - 可**逐条处理的工作队列** + 选中后展开 **AI 的详细分析/判断过程**（如分诊台）；
   - 可**调参数/切策略**并**实时影响全局**（如评分策略切换重排全池）；
   - **多步骤**操作、可推进的状态机（如陪练）。

5. **操作必须有后果闭环**
   用户的操作要产生**可见的下游变化/后果**：推送内容→看到客户反应→AI 自动跟进；
   执行资金方案→缺口图表被填平、预警解除；处置风险→风险计数下降。不能只弹个 toast。

6. **零装饰性数据**
   禁止"为呈现而呈现"的数字/KPI/统计。每个元素都必须是**老板/用户能据此决策、
   AI 真帮得上忙的行动点**。把纯展示一律替换成「AI 已识别 / 待你处理 / 一键处置」。

7. **站在老板视角的价值**
   每个功能都要能说清：替老板**省钱 / 赚钱 / 避险 / 做决策**，让企业愿意付费。

8. **交付前必须用 jsdom 真实 DOM 跑通验证**
   每次交付前，用 jsdom 加载整页、**逐一模拟点击所有交互**，确认 0 运行时错误、
   全部断言通过，绝不交付空白页/坏页。变量、引号等低级错误用此关卡兜住。

## 自检清单（交付前逐条对照）
- [ ] 是否有"只能看"的环节？→ 必须改为可交互
- [ ] 是否有"点一下只弹文字"的浅层交互？→ 至少关键环节要做成队列+详情/可调参数/多步
- [ ] 操作后有没有可见后果？→ 状态变更/计数/图表/下游联动
- [ ] 有没有装饰性数字？→ 删掉或改成可操作项
- [ ] 每个板块够不够"厚"？→ 对标销冠AI助手阶段2(分诊台)/阶段3(推送闭环)的厚度
- [ ] jsdom 是否全绿？
