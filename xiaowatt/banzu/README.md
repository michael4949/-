# 小瓦特·班 · 班组长 AI 助手（项目二工作区）

业务方：光明供电局（联系人林洁怡）。权威规格＝`../docs/正式交付物/` 两份班组文档（需求 V1.0 / 技术 V1.0）+ 甲方 9/3 定稿的设计方案 v0.5 + **9/12 六份材料的口径**（组织管理六维、修改建议、负责人反馈单、关键节点管控表、星级评价标准分册、配网自动化周报第 29 期）。本文是开发视角的浓缩，规则见 `../docs/02_已定决策.md` 第 43 条。

## 一句话定位

一位有形象的班组长助手「小瓦特」，坐在班组台账、关键节点表、周报和能力图谱之上，替**光明供电局配网管理部配电自动化班**的班长看、想、写、办、记；同一套数据再往上一层，给**管理者**（配网管理部主管，管辖三个班组）一个俯瞰全流程的视角。**页面是舞台，班长照常点按钮，每一次点击之后屏幕上出现的是她在做。** 所有涉及人的结论固定「由班组长确认后使用」，不出等级、不打分。

## 三条原则（甲方 9/3 确认）+ 两条铁律（9/4、9/9）

1. **点击是班长的手，动画是小瓦特的手。** 结果是过程的尾声。
2. **能点的东西都会"回应"。** 人名可点、数字可点、周报指标可点、文稿段落可点；界面上没有点不动的按钮。
3. **语音是快捷键，不是入口。** 所有语音路径都有等价的点击路径。
4. **页面只读 `DB`，按钮只写 `DB`**：派工 / 审票 / 开工 / 回传 / 完工 / 验收 / 添加任务 / 上传两票 / 节点勾清 / 资格确认 / 跨班组调配，每一步都改变后面每一页的数字。
5. **画像要能回答"这个人几斤几两、这个班组缺什么"**：每个数都指到台账，与台账中心同源可跳转核对。

## 主线（八分钟演示的骨架，案例日期 2026-08-07 周五 · 周报第 29 期发布日）

周报到了 → 她把光明局排名靠后的项对到关键节点表，请班长按周报排本周重点 → **田寮站 F02 田玉四线自动化改造工程 · 交接试验与成套设备验收**（下周一）派工：四条规则（证书 / 九类核心技能资格 / 本周工时 / 当天冲突）逐人给出**推荐、随队、排除的理由表**，班长点人她说人，按她的安排或换人 → 派工单落 DB，工作票自动起草，班前会材料按派工单写 → 主线任务走 **审票（缺项圈出、补齐）→ 开工（票没审过不放行）→ 回传 → 完工（记工时、票已执行、缺陷转待验收）→ 九类核心技能实操量回写到本人画像** → 班组画像五类指标随之变化 → 切到管理者：部门态势热力、全流程九格、风险清单发督办、跨班组调配先模拟影响再发起 → 切回班长确认。

## 验收

1. 八分钟演示只用鼠标可走完；两个角色各走一遍主线。
2. 派工卡上每个人都有"为什么推荐 / 为什么排除"的理由，理由随派工单存进台账；换一个被排除的人她说出原因。
3. 主线任务从审票到完工每一步都改变工时、票、缺陷、关键节点、画像实操次数与培养页；刷新后不丢。
4. 班组画像：五类指标每项都有阈值、来源、责任人并可跳台账；履职证据不出分数、不出等级；核心技能资格只由班长确认。
5. 周报第 29 期 21 项指标与关键节点表 19 项互相对得上；周报排名靠后项在工作台、用工安排、台账中心三处一致。
6. 管理者视角：分层不排名；督办、提醒、调配、梯队建议全部落到班长的通知或确认；星级对标 8 项权重与分册一致，64 条建设工作条目取自分册。
7. 人物全部虚拟；grep「演示|待建|下一版本|比赛|评委|一期|人力资源部|所里|所长」在界面文字零命中（讲师演示台除外）；smoke 的「禁词」断言覆盖工作台、用工安排、培养、画像、台账、知识库、部门态势、履职、星级、配置。
8. 需求文档 V1.0 的七条与 9/12 六份材料的修改点逐条覆盖（对照表见 `../docs/02_已定决策.md` 第 43 条）。
